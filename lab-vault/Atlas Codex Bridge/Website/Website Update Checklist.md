# Website Update Checklist

Use this checklist before asking Codex or another wing to edit the GitHub Pages website.

## Inputs

- Obsidian source note.
- Public artifact path.
- Desired website location.
- Claim status.
- Non-claims.
- Link target.
- Preview requirement.

## Required Public Copy Fields

For papers:

- title,
- subtitle,
- one-paragraph public summary,
- status: draft / pre-circulation / public / staging,
- link to PDF,
- one-sentence claim ceiling.

For experiments:

- experiment title,
- scene or run ID,
- what the viewer shows,
- what it does not show,
- link to full artifact,
- status badge.

For lab notes:

- short title,
- internal source note,
- public claim boundary,
- next-gate or open problem.

## Claim-Safety Pass

Check for forbidden drift:

- no new field equation unless explicitly in a paper,
- no GR replacement language,
- no material spacetime lattice,
- no observational claim without observational audit,
- no dark matter/dark energy implication unless a specific result forces discussion,
- no "solved handoff" language,
- no "quantum" claim from Omni-Scope or micro-world scratch results.

## Link Check

Confirm:

- local file exists,
- URL matches filename case and spaces,
- PDF link opens,
- mobile page layout remains readable,
- news/homepage links do not duplicate stale copies.

## Preferred Website Rhythm

Public site updates should be fewer and stronger than vault updates.

Good cadence:

- major paper release,
- major result note,
- breakthrough arc synthesis,
- polished interactive viewer,
- public-facing simulation summary.

Avoid:

- every scratch run,
- every doctrine correction,
- every internal speculation note,
- raw lab enthusiasm without claim boundary.
