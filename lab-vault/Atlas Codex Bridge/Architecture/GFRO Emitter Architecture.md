# GFRO Emitter Architecture

This note records the current architecture correction: Atlas has evolved from a query/extraction-centered posture toward a GFRO emitter posture.

## Core Shift

Older posture:

```text
queries extract structures
```

Current posture:

```text
GFRO builds a derived source/context relation map
the field-sieve emits coordinate candidates from that map
Node -1 records the emitted diagnostic registry
witnesses rank emitted candidates
retention certifies surviving scaffolds
GR decides interpretation
```

## Default Serious GFRO Pipeline

```text
1. scene passport
2. Node 1 parent/context declaration
3. Node 2+ source roster freeze
4. datum/witness roster freeze
5. source/datum map
6. GFRO relation-map declaration
7. operator/residual declaration
8. field-sieve coordinate-emission rule
9. compact Node -1 emitted ledger
10. diagnostic object registry
11. validation witnesses
12. retention ranking
13. render after ledger
14. interpretation after claim-status check
```

## Diagnostic Object Registry

Where applicable, the emitted registry may include:

- zero sets
- faces
- seams
- junctions
- pockets / source support envelopes
- handoff supports
- low-margin regions
- entropy tags
- tensor/eigenframe handoff witnesses
- source-perspective omni witness links
- Node P candidates
- Node A candidates
- wireframe scaffold candidates
- Lumen Lattice / Released Coherence Lattice links, when declared

## Role Boundaries

- GFRO-emitted structures are diagnostic objects.
- They are not physical sources.
- They are not force barriers.
- They are not automatic observables.
- They do not modify GR.
- They require ledger evidence and claim-ladder discipline.

## Query Role After This Shift

Queries remain useful, but downstream:

- inspect emitted ledgers,
- filter registries,
- compare branches,
- build views,
- support review.

Queries do not define the primary engine grammar.
